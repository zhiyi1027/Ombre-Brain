# GitHub 加密业务备份

旧 `GitHubSync` 仅递归小写 Markdown，不能当作完整业务备份。新入口使用
`sealed_github.py` 和 grey-kit `runtime/ob_github.py`，不导入服务器或模型。
Vega 的 `OB_GITHUB_SEALED_ONLY=1` 会在旧配置保存、上传、合并恢复和
预恢复明文 ZIP 之前拒绝旧路径；它不会自动关闭仍在旧机器上的程序。

范围版本 `ob-business-no-images-no-raw-v1`：核心/普通/归档桶、feel、plan、
信件、昨日印象及修改/便签历史、私有连续性、夜梦，支持 Markdown、JSON、
文本及明确的业务数据库。图片文件排除，媒体文字说明保留；原文 `_raw`、
配置/登录/密钥、未知根目录、日志/队列及旧备份不纳入。已识别业务目录中
遇到未知类型、链接或扫描失败会拒绝完整成功，不静默跳过。

向量数据库用 SQLite 在线快照；书记员数据库保留事实/发布状态和预算，清除
临时模型响应缓存及租约并 VACUUM。未知表/视图/触发器需复审。源数据不修改。
复制前后重新枚举并计算内容指纹，包含活跃 WAL；有增删改就失败重试。
这仍是有限检查窗口，不声称全库原子或检查后不会再写入。

包内路径、大小和 SHA 清单整体加密。程序先在私有目录做明文恢复校验，再用
固定 age 程序和已有恢复公钥封装。临时明文在正常及可捕获失败时清理，强杀或
断电可留下私有暂存；下次会拒绝并等待核对。不会读取恢复私钥或请求口令。

Git 仅传输 `index.json` 汇总与 `backups/时间随机ID/vault.age`，不传私有路径
清单。SSH 使用本仓库专钥、固定 host key、不继承 Git helper/hook/登录材料。
入口先固定密文 FD 并验 hash/age header，推前复验真正暂存的 Git blob，
使用预期 HEAD lease；推后在全新对象库重新取回密文并验 SHA。已有未知 HEAD
不自动接管，也不下载旧明文分支；首次试传必须用新分支。

每代是无父提交，当前树最多留 7 份密文，防止版本沿旧明文历史继续累加。
旧不可达对象的后台 GC、缓存、PR 引用和他人 clone 不由改分支保证消失；
敏感历史彻底清理可能需 GitHub Support。不要把当前树没有明文说成全网擦除。

正式清旧历史之前须齐备：新范围快照、远端独立读回、受保护身份实际解密、
新目录逐文件恢复与 SQLite 校验、独立复审、最后源端无漂移、旧明文写入者
停止或撤掉写权限。只删除 HEAD 文件不能清历史。旧恢复基线及原归档继续保留。

测试均用生成资料；Git 传输测试中的 age 形状字节不冒充加解密实测：

```sh
PYTHONPATH=src python -B -m unittest discover -s tests -p test_sealed_github.py -v
```
