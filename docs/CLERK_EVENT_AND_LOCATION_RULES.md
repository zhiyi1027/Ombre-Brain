# 昨日印象选材与地点承诺

“发生了什么”最多8条，不凑满。同等类别下先保留具体、有画面的经历：在哪儿做了什么、看见或买到了什么，以及当时的反应。裸泛句（如仅说人多或热闹）不挤掉已有的同类具体事件，原卡仍可检索；具体而简短的事实不会按长度降级。之后保留模型推荐顺序到完整卡池重选和预算裁剪；同一事件的重复描述不占多条。身体、饮食、心情等栏位仍保留，整份印象的1000字符/900估算token预算与breath总预算不增加。

地点承诺只对**本次逗留**生效。当前实现是保守的本机语法规则，没有新增模型请求、定位服务或后台任务：

- 例如“离开南京前喝杯茶”“这次在南京期间带你逛灯会”可以绑定；裸“在南京期间”还需要同会话、没有缺口阻断的当前在场正证。“明天离开前”需要已明确的当前地点，否则保留为未绑定候选。
- 地点和主体都必须有原话依据。多分句不能把别人的逗留继承给知知；下次、未来年份、每次、长期、假设、愿望、回忆等不能绑定为当前逗留。
- 离开证据要求知知说出的明确我方已离开陈述，例如“我已经离开南京了”。省略主语、别人离开、准备离开、假设或回忆不会触发。只按明确的同名地点匹配；离开酒店不等于离开城市，不从回家、断联、时间流逝或另一个地点名称推断离开。
- 时间是观察到该陈述的消息时间，不臆造真实离开的精确时刻。只应用晚于承诺、且不晚于查询时刻的有效离开证据；之后重新回来不会复活旧约定，新承诺按新的绑定时间处理。

这是派生有效期，不改原正文或人工`status`，不把过期当作完成，也不触发resolved联动。候选仍留在历史记录，默认候选搜索排除过期项，`include_expired=True`可带原因读取；过期候选不能直接确认入plan。正式plan确认时只向相同正文或仍明确同一地点条件的改写继承绑定，避免给长期承诺嫁接地点。

所有活动plan读口共用派生状态：plan检索、两种启动布局和Web看板。Web将地点过期单列，原status仍保留。用户确认的普通plan正文若明确写了本次离开条件，也可计算地点有效期；无明确地点的旧plan不会被猜测补齐。

跨天索引读取全部有效书记员发布的筛后证据，不依赖是否入选昨日印象，也不受搜索条数限制。一次请求共用一个索引和一次归档过滤快照；没有地点范围或已经人工关闭的plan先短路。来源和离开两侧都随当前源版本重新核验，证据失效时撤回派生过期判断，不修改原来的人工状态。

这套规则宁可暂不判定。未识别的昵称、地点别称、复杂省略、跨会话指代或隐含旅行关系仍待明确证据；合成检查通过不等于通用自然语言理解或真实多日验收。自动夜跑和正式接班仍由既有独立开关控制。
